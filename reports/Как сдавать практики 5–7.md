## Подготовка перед демонстрацией

1. На своём ПК запусти VirtualBox и виртуальную машину `DevOps`. Дождись загрузки Ubuntu.
2. Если включена AmneziaVPN, сохрани исключение для `192.168.56.101`.
3. Открой в браузере `https://devops.local/` и `https://devops.local/app/`.
   Для учебного самоподписанного сертификата браузер может показать предупреждение;
   доверие сертификату отдельно демонстрируется командой curl с `--cacert`.
4. Держи рядом три отчёта, репозиторий, PR №3 и окно снимков VirtualBox.
5. Открой PowerShell и подключись к VM командой `ssh devops`.

Псевдоним `devops` уже настроен в Windows SSH config: пользователь devops,
отдельный ключ и порт 2222. Если `sudo` запрашивает пароль, введи пароль Ubuntu;
при вводе символы в терминале не отображаются.

## Короткая демонстрация

### Общая готовность — в терминале Ubuntu после ssh

```bash
sudo bash ~/devops-course-2026/scripts/audit.sh
echo $?
```

Ожидается `Passed: 14; failed: 0`, затем код `0`. В итоговом состоянии скрипт
проверяет сразу SSH, UFW, Nginx и Docker. В отчёте №5 сохранён более ранний
запуск из шести проверок, а в №6 — из десяти; это этапы развития одного сценария.

### Практическая №5 — SSH, UFW, снимки

```bash
sudo sshd -T | grep -E '^(port|permitrootlogin|passwordauthentication|maxauthtries) '
sudo ufw status verbose
```

Покажи порт 2222, `permitrootlogin no`, `passwordauthentication no`,
`maxauthtries 3`, активный UFW с deny incoming и LIMIT для 2222.
В VirtualBox покажи снимки `01-clean-install`, `02-keys-configured`,
`03-ssh-hardened`. Объясни различие `known_hosts` и `authorized_keys`.

### Практическая №6 — сайт, TLS, доставка

В PowerShell компьютера выполни:

```powershell
curl.exe -I http://devops.local/
curl.exe --cacert "$env:USERPROFILE\devops.crt" -I https://devops.local/
curl.exe --cacert "$env:USERPROFILE\devops.crt" -I https://devops.local/no-such-page
```

Ожидаются 301 с Location HTTPS, 200 и 404 соответственно. Покажи главную
страницу с ФИО и группой, собственную страницу 404, `scripts/deploy.sh` и
пять результатов его проверки в отчёте. В VM можно показать `sudo nginx -t`.
Объясни права 755/644, назначение SAN, отличие `reload` от `restart` и флага
`--cacert` от отключения проверки через `-k`. Покажи снимок `04-nginx-https`.

### Практическая №7 — контейнеры и прокси

В терминале Ubuntu:

```bash
cd ~/app
docker compose ps
docker compose exec -T --interactive=false app id
sudo ss -tlnp | grep -E ':(5000|5432)\b'
stat -c '%a %n' .env
```

Ожидаются два сервиса, `healthy` у базы, пользователь `app` (uid 999),
слушатель только `127.0.0.1:5000`, отсутствие публикации 5432, права `.env` 600.
В PowerShell:

```powershell
curl.exe --cacert "$env:USERPROFILE\devops.crt" https://devops.local/app/
curl.exe --cacert "$env:USERPROFILE\devops.crt" https://devops.local/app/
curl.exe --cacert "$env:USERPROFILE\devops.crt" https://devops.local/app/health
```

Два первых запроса увеличивают Visits, последний отвечает `ok`. Покажи
`app/Dockerfile`, `app/docker-compose.yml`, раздел 9 инструкции и снимок
`05-docker-compose`. Объясни, как имя `db` разрешается в сети Compose,
зачем healthcheck и почему приложение опубликовано на loopback.

## Как отвечать на вопросы об опытах

Отрицательные проверки уже выполнены, протоколы и скриншоты включены в отчёты.
Открывай соответствующий раздел и объясняй «что изменили → какой результат
получили → почему → как восстановили»:

- №5: MaxAuthTries 10 приводит к коду аудита 1; штатное значение 3 возвращает 0.
- №6: файл 600 даёт 403; каталог 711 позволяет читать известный файл, 744 — нет;
  ошибочная доставка с правами 666 допускает подмену, штатный deploy возвращает 644.
- №7: без базы `/health` даёт 200, главная — 500; остановленный app даёт 502 в Nginx;
  `down` сохраняет том, а `down -v` удаляет данные; публикация на всех адресах
  выявляется аудитом. Опыт с удалением тома выполнен на учебной базе.

Перед защитой прочитай ответы на контрольные вопросы в конце основной части
каждого отчёта: 14 вопросов в №5, 14 в №6 и 8 в №7. Не включай пароли,
закрытые ключи и содержимое `.env` в отправляемые материалы.

Основание: раздел 8 методички №5 (с. 17), раздел 9 методички №6 (с. 19),
раздел 8 методички №7 (с. 13). Демонстрационный маршрут выше — практический
порядок показа выполненных условий; конкретный порядок защиты определяет преподаватель.
